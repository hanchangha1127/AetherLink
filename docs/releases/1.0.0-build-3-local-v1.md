## Release Summary

- Android Release and the macOS package share marketing version `1.0.0` and
  build number `3` through `release/version-ledger.tsv`. Android Debug remains
  `0.1.0+1`.
- Android Release enables R8 code/resource shrinking and contains only the V1
  `arm64-v8a` ABI. The archived AAB contains one DEX, all five app locales,
  five JNI libraries, and a byte-identical R8 mapping.
- The macOS package is a thin Apple Silicon Release build with all five
  localized tables embedded in the app and a UUID-matched dSYM.
- Six generated Gradle lock files cover the settings, buildscript, and clean
  Release-resolved graphs. SwiftPM currently has no external dependencies.
- One canonical normalized-input archive retains both platform payloads,
  mappings, symbols that are available, dependency metadata, the exact source
  inventory, and an independently verified manifest.

## No-Device Provider Compatibility Fixture

The recorded-date fixture below separates official release candidates from
what was actually present on the local runtime host. On 2026-07-29, official
release records identified Ollama `0.32.5` and `0.32.4` plus LM Studio
`0.4.20` build 1 and `0.4.19` build 2 as the current/previous candidates.
The host instead exposed Ollama `0.32.4` and LM Studio `0.4.17-beta+3`.

Localhost catalog/version response shapes and focused default backend tests
passed first. Official Ollama Darwin archives for both candidates were then
SHA-256 verified and run from a temporary directory on unique localhost ports.
The empty-catalog phase passed exact-version, health, cold-start, restart, and
stopped-endpoint checks. A separate model-backed phase automatically selected
one already-installed, unloaded chat model, copied only its manifest and
content-addressed blobs into candidate-local copy-on-write snapshots, and
passed populated-catalog, streamed completion, first-delta cancellation,
post-cancel recovery, confirmed unload, installed-state preservation, restart,
snapshot-integrity, and stopped-endpoint checks for both candidates. No model
was pulled or downloaded. A dedicated additional-shape phase selected the
exact second of three installed completion-capable candidates and passed the
same chat lifecycle matrix for both versions after cold start and restart,
without fallback or retained model identity. A second isolated model-backed
phase selected one already-installed, unloaded embedding model and passed two-input embedding
shape, residency, confirmed unload, restart, snapshot-integrity, and
stopped-endpoint checks for both candidates. A third phase selected one
already-installed, unloaded `vision + completion` model and passed text chat,
fixed-PNG attachment, first-delta cancellation, post-cancel recovery, residency,
confirmed unload, restart, snapshot-integrity, and stopped-endpoint checks for
both candidates. This remains a bounded
compatibility smoke. It does not qualify either provider candidate, establish a
minimum supported version, prove semantic quality by itself, generalize across
model shapes, or qualify LM Studio. The separate semantic-quality gate below
covers only four fixed English ranking scenarios. Model names, catalog
contents, prompts, image
bytes, provider outputs, embedding inputs, and vector values are intentionally
not retained; only bounded source and snapshot shapes are recorded.

### Exact Ollama Model-Backed Runner Readback

The same runner's explicit `--model-backed` mode reads the installed default
Ollama server only to verify its exact version, catalog shape, and initially
unloaded model selection. It automatically selects the smallest local
completion-capable model, resolves its manifest by digest, verifies every
content-addressed blob size and SHA-256 digest, and makes candidate-local
`clonefile` copy-on-write snapshots. It passes the selected model ID only to the
runner-local Swift test environment, never emits or retains it in canonical
evidence, and never calls a pull endpoint. Every CLI failure after entering a
model-backed mode runs through an identifier-free diagnostic boundary. The runner
compares the source provider version, catalog `name`/`digest`/`size` projection,
running-model identity set, and selected source-file bytes before and after the
matrix; all remain unchanged. Unselected model-store bytes and unprojected
catalog metadata are outside this comparison. Each exact candidate then
runs the fail-closed adapter test after cold start and restart. The test
requires a populated one-model catalog, bounded streamed completion,
cancellation after the first provider delta, post-cancel completion, confirmed
unload with installed-state preservation, and continued health. The runner also
requires the snapshot SHA-256 state to remain byte-for-byte unchanged and every
candidate endpoint to close after stop.

On an injected adapter-phase failure after process creation, the model-backed
phase still stops the provider and rehashes the candidate snapshot. Separate
candidate-level injection replaces candidate execution, then proves the outer
matrix removes its temporary root before repeating the observed source
readback. Provider-version, catalog identity-projection, running-set, or
selected-file drift is rejected before an otherwise unchanged candidate error.
Seven deterministic unit regressions cover these paths and the Popen/stop/
snapshot-error priority without starting a real provider. They do not establish
OS-kill, power-loss, cleanup-permission, or concurrent external-mutation
behavior.

### Exact Ollama Additional Chat-Shape Readback

The dedicated additional-shape runner selects the second-smallest installed
model that explicitly reports `completion`, requires that exact recorded
snapshot and capability tuple, and fails if the target is already running
rather than falling back to another model. It resolves and verifies the
manifest plus 991 content-addressed blobs, then uses the existing chat lifecycle
assertion against candidate-local copy-on-write snapshots. The 16,679,502,421-
byte model artifact and 213,712-byte manifest remain execution inputs; no model
download is attempted. The recorded target reports exactly `completion`,
`thinking`, and `tools`, and does not report `vision`.

Both exact Ollama candidates passed cold-start and restart runs, for four
observations total. Every observation covered populated catalog, streamed
completion, first-delta cancellation, post-cancel recovery, unload with
installed-state preservation, snapshot integrity, and stopped-endpoint
unavailability. After temporary cleanup, the source provider version, catalog
identity and capability projections, running identity set, selected source
bytes, and bound runner/assertion sources were unchanged. Cleanup residue,
including a dangling symlink, prevents source readback rather than being
reported as a completed run.
