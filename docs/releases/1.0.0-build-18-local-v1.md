## Android Backup And Device-Transfer Contract

Build 18 retains `android:allowBackup="false"`. The packaged values are
`allowBackup=false`, `dataExtractionRules=@xml/data_extraction_rules`, and
`fullBackupContent=@xml/backup_rules`.

The legacy full-backup resource excludes `root`, `file`, `database`, `sharedpref`, and `external`, each with `path="."`.
The Android 12+ resource contains exactly `cloud-backup` and
`device-transfer`; each section excludes those five domains plus `device_root`, `device_file`, `device_database`, and `device_sharedpref`, again with
`path="."`. No `<include>` rule is present.

The builder and independent checker bind the APK manifest fields to the
packaged resources and parse the compiled policy bodies. For the AAB, they
require `bundletool validate`, inspect the base manifest, materialize a
temporary AAB-derived universal APK, and apply the same compiled XML body
checks. Temporary readback signing material is local to the inspection
directory and is not a production signing identity.

The exact tools are `aapt2 dump xmltree + resources --no-values` and
`bundletool dump manifest`.

The manifest records:

- `apkManifestReadback.member=android/apk/app-release-unsigned.apk`
- `apkManifestReadback.verifiedFields=[allowBackup, dataExtractionRules, fullBackupContent]`
- `bundleManifestReadback.member=android/bundle/app-release.aab`
- `bundleManifestReadback.verifiedFields=[applicationId, minSdk, targetSdk, versionCode, versionName, allowBackup, dataExtractionRules, fullBackupContent]`

Build 15 is the first local release that requires both APK and AAB backup-policy manifest readback.
Build 17 retains the Build 15 packaged backup-policy contract and adds compiled XML body readback for both the APK and an AAB-derived universal APK.
Builds 1 through 16 remain historical and are not reinterpreted as Build 17 backup-policy evidence.
Build 18 retains that packaged-policy contract. This evidence does not claim
that an Android vendor, cloud service, or physical device performed backup or
transfer.
