## Android Bundle Structure Validation

The builder and the independent readback verifier each use the
AGP-resolved, exact `bundletool 1.18.3` runtime. They first run
`bundletool validate` with a 60-second process timeout and require the module
set to be exactly `base`; they then run `bundletool dump manifest` against the
same temporary AAB and verify application ID, minimum and target SDK, version
code, and version name. Standard-error output, timeout, invalid structure,
module drift, or manifest drift fails closed. Build 11 records the canonical
`bundleStructureValidation` claim; Builds 1 through 10 retain their historical
manifest field sets while the current verifier still executes actual
validation against their archived AAB bytes.

## Compatibility And Transition Boundary

- Android Release and macOS package metadata use `1.0.0+11`. Android Debug
  `0.1.0+1` remains a separate, non-migratable development lineage.
- Android is unsigned, `arm64-v8a`-only, minimum API 26, and target API 36.
  The macOS package is local ad-hoc, Apple Silicon `arm64`, and macOS 14+.
- There is no prior production predecessor. N/N-1 is not yet qualified.
- Production signing, notarization, store upload, deployment, clean-machine
  launch, provider-backed Runtime behavior, and physical-device execution are
  not claimed.
- Authentication, owner-proof, governance, and security work are excluded from
  this qualification.

## Rollback Posture

No production rollback package is claimed. Android channel rollback must use a
compatible semantically older build with a higher `versionCode`; ordinary
downgrade installation is not a supported recovery path. A future macOS
rollback should use the current or immediately previous signed DMG only after
compatibility and migration checks, not this local ad-hoc archive.
