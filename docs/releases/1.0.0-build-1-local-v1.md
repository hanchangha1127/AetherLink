# AetherLink 1.0.0 Build 1 Local V1 Qualification Record

Status: local release-engineering candidate, not a production release.

Release ID: `aetherlink-1.0.0+1-local-v1`

This record combines the release notes, compatibility matrix, transition
guidance, known limitations, support diagnostics, privacy boundary, and
rollback posture for the current local candidate. It describes only evidence
that can be reproduced without installing either app or using a physical
device. It does not authorize signing, upload, deployment, or distribution.

## Release Summary

- Android Release and the macOS package share marketing version `1.0.0` and
  build number `1` through `release/version-ledger.tsv`. Android Debug remains
  `0.1.0+1`.
- Android Release enables R8 code/resource shrinking and contains only the V1
  `arm64-v8a` ABI. The archived AAB contains one DEX, all five app locales,
  five JNI libraries, and a byte-identical R8 mapping.
- The macOS package is a thin Apple Silicon Release build with all five
  localized tables embedded in the app and a UUID-matched dSYM.
- Six generated Gradle lock files cover the settings, buildscript, and clean
  Release-resolved graphs. SwiftPM currently has no external dependencies.
- One canonical normalized-input archive retains both platform payloads,
  mappings, symbols that are available, dependency metadata, the exact source
  inventory, and an independently verified manifest.

## Installation And Migration

This candidate has no approved production package/signing lineage and must not
be treated as an upgradeable production build.

- Android Debug `0.1.0+1` is non-migratable. A future production release must
  use a clean install and fresh pairing unless a separately implemented and
  tested migration path supersedes this decision.
- The unsigned Android candidate cannot establish Play upgrade compatibility.
  Do not infer that its application ID alone makes it upgradeable.
- Existing local ad-hoc macOS packages are not an approved update lineage.
  Configuration or paired state must not be assumed portable to a future
  signed package.
- There is no prior canonical production V1 release from which to prove N/N-1.
  The next no-device qualification slice must therefore encode and test either
  an explicit fresh-pair transition or a declared compatible predecessor before
  any upgrade claim is made.

No user-data, configuration, pairing-state, or uninstall/reinstall preservation
claim is made by this document.

## Rollback Posture

The local candidate has not been deployed, so it has no executable production
rollback action.

- For the selected future Android channel, rollback means stopping a rollout
  and shipping a corrected build with a higher `versionCode`; it does not mean
  installing a lower version.
- For the selected future macOS direct-distribution channel, only the current
  or immediately previous approved signed DMG may be restored, and only after
  its state compatibility has been demonstrated.
- Until a signed release lineage and N/N-1 state matrix exist, the safe
  development recovery posture is a clean install and fresh pair. This is a
  limitation, not completed rollback proof.

## Known Limitations

- Android is unsigned. macOS is locally ad-hoc signed. Final application
  identities, Play signing, Developer ID signing, notarization, stapling, and a
  signed DMG are not present.
- Neither artifact has been installed or launched by this qualification run.
  Clean-machine install, upgrade, rollback, uninstall, reboot, and recovery are
  untested.
- Physical camera/QR, accessibility, lifecycle, live-provider, and network
  flows are outside this record.
- Android and macOS are both arm64-only. Intel macOS remains Post-V1.
- Android native dependency inputs arrived pre-stripped, so no native-symbol
  archive is available. The manifest records
  `unavailable-upstream-prestripped`.
- Raw AGP and dSYM diagnostic payloads retain build-host paths. The archive is
  deterministic only for its declared normalized local inputs; cross-checkout
  and cross-machine reproducibility are unproven.
- The clean Release dependency graph is locked except for the declared
  `org.jetbrains.kotlin:kotlin-stdlib-common` configuration-membership
  compatibility exception. Its parent `kotlin-stdlib:2.3.21` remains locked.
  Debug, test, and androidTest dependency graphs are outside this lock claim.
- Release lint passes with zero errors and three remaining notices:
  `OldTargetApi`, `GradleDependency`, and the scoped `DataExtractionRules`
  notice.
- The current/previous Ollama and LM Studio candidates are now pinned as a
  dated snapshot, but minimum supported versions and full compatibility
  qualification remain unresolved.

## Privacy And Evidence Boundary

This local workflow does not install, launch, upload, or distribute either
application. Its declared payload contains compiled artifacts, build metadata,
mapping/debug information, and a repository-relative source-file inventory.
Some diagnostic payloads contain build-host paths, so the container should be
treated as internal release-engineering material. This record makes no
secret-scan, runtime-data, telemetry, or production privacy-audit claim.
