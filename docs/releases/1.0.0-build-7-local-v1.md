## Dependency And License Inventory

The source-controlled catalog exactly covers 350 unique Maven coordinates from
all six Gradle lock files. SwiftPM has zero external dependencies. Each Maven
record retains its exact coordinate, configurations, lock-file membership,
PURL, POM URL chain, POM byte size and SHA-256, and the POM-declared license
name and URL. The catalog contains 379 POM records: 221 from Google Maven and
158 from Maven Central after parent inheritance is resolved.

The release build and independent readback are offline. The public repositories
are contacted only by the explicit maintenance command:

```sh
python3 -B script/generate_release_compliance.py refresh
```

The SPDX document describes the AetherLink root plus 350 locked Maven packages,
with 350 one-per-package precedence-compressed V1 relationships: 202 runtime,
141 build dependency, and 7 generic dependency. This historical mapping lost
additional roles for 200 multi-role packages; Build 8 corrects that semantic
limitation with 692 exact role relationships. Every package uses
`filesAnalyzed=false`; no Maven binary checksum or transitive package-to-package
edge is invented.

The catalog stores POM URL, byte size, SHA-256, and parsed declarations.
Original POM bodies and license/NOTICE texts are not archived. Historical
offline readback therefore does not re-fetch or re-parse the originals and
does not prove POM authenticity, attribution/notice completeness, binary or
source license coverage, compatibility, or legal conclusions.

Manifest schema 2 makes these four compliance members mandatory from Build 7.
The independent checker reconstructs the SPDX and text inventory bytes from the
archived catalog and fixed metadata, cross-binds the catalog's six lock-file
identities to the manifest and source snapshot, and rejects coordinate,
configuration, PURL, license mapping, relationship, count, or byte mutations.
Historical Builds 1 through 6 retain manifest schema 1 and must not contain
`compliance/` members.

## Compatibility And Transition Boundary

- Android Release and macOS package metadata use `1.0.0+7`. Android Debug
  `0.1.0+1` remains a separate, non-migratable development lineage.
- Android remains unsigned, `arm64-v8a`-only, minimum API 26, and target API
  36. The macOS package remains local ad-hoc, Apple Silicon `arm64`, and macOS
  14+.
- There is no prior production predecessor. N/N-1 install, state, pairing, and
  protocol behavior are not yet qualified.
- Production signing, notarization, store upload, deployment, clean-machine
  launch, physical-device execution, and provider-backed runtime behavior are
  not claimed.

## Rollback Posture

No production rollback package is claimed. Android channel rollback must use a
compatible semantically older build with a higher `versionCode`; ordinary
downgrade installation is not a supported recovery path. A future macOS
rollback should use the current or immediately previous signed DMG only after
compatibility and migration checks, not this local ad-hoc archive.
