## Android Backup And Device-Transfer Contract

Build 17 retains `android:allowBackup="false"`. The packaged values are
`allowBackup=false`, `dataExtractionRules=@xml/data_extraction_rules`, and
`fullBackupContent=@xml/backup_rules`.

The legacy full-backup resource excludes `root`, `file`, `database`, `sharedpref`, and `external`, each with `path="."`. The Android 12+ resource contains exactly `cloud-backup` and `device-transfer`; each section excludes those five domains plus `device_root`, `device_file`, `device_database`, and `device_sharedpref`, again with `path="."`. No `<include>` rule is present.

The builder and independent checker use
`aapt2 dump xmltree + resources --no-values` to bind the APK manifest fields to
the packaged resources. They additionally parse the compiled
`res/xml/backup_rules.xml` and `res/xml/data_extraction_rules.xml` bodies.
For the AAB, they require `bundletool validate`, inspect the bundle manifest,
using `bundletool dump manifest`, materialize a temporary AAB-derived universal
APK, and apply the same compiled XML body checks. Temporary readback signing
material is local to the inspection directory and is not a production signing
identity.

The manifest records:

- `apkManifestReadback.member=android/apk/app-release-unsigned.apk`
- `apkManifestReadback.verifiedFields=[allowBackup, dataExtractionRules, fullBackupContent]`
- `bundleManifestReadback.member=android/bundle/app-release.aab`
- `bundleManifestReadback.verifiedFields=[applicationId, minSdk, targetSdk, versionCode, versionName, allowBackup, dataExtractionRules, fullBackupContent]`

Build 15 is the first local release that requires both APK and AAB backup-policy manifest readback.
Build 17 retains the Build 15 packaged backup-policy contract and adds compiled XML body readback for both the APK and an AAB-derived universal APK.
Builds 1 through 16 remain historical and are not reinterpreted as Build 17 backup-policy evidence.

This is packaged-policy evidence only. It does not claim that an Android vendor,
cloud service, or physical device actually performed backup or transfer.

  `0.1.0+1` remains a separate, non-migratable development lineage.
- Android is unsigned, `arm64-v8a`-only, minimum API 26, and target API 36.
  The macOS package is local ad-hoc, Apple Silicon `arm64`, and macOS 14+.
- There is no prior production predecessor. N/N-1 is not yet qualified.

  launch, provider-backed Runtime behavior, and physical-device execution are
  not claimed.
- Security, authentication, owner-proof, and governance work are outside this
  non-security qualification.

## Rollback Posture

No production rollback package is claimed. Android channel rollback must use a
compatible semantically older build with a higher `versionCode`; ordinary
downgrade installation is not a supported recovery path. A future macOS
rollback should use the current or immediately previous signed DMG only after
compatibility and migration checks, not this local ad-hoc archive.
