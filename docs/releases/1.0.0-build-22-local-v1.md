## Android Backup And Device-Transfer Contract

Build 22 retains `android:allowBackup="false"`. The packaged values are
`allowBackup=false`, `dataExtractionRules=@xml/data_extraction_rules`, and
`fullBackupContent=@xml/backup_rules`.

The legacy full-backup resource excludes `root`, `file`, `database`,
`sharedpref`, and `external`, each with `path="."`. The Android 12+ resource
contains exactly `cloud-backup` and `device-transfer`; each section excludes
those five domains plus `device_root`, `device_file`, `device_database`, and
`device_sharedpref`, again with `path="."`. No `<include>` rule is present.

The builder and independent checker bind the APK manifest fields to the
packaged resources and parse the compiled policy bodies. For the AAB, they
require `bundletool validate`, inspect the base manifest, materialize a
temporary AAB-derived universal APK, and apply the same compiled XML body
checks. The exact tools are `aapt2 dump xmltree + resources --no-values` and
`bundletool dump manifest`.

Build 15 is the first local release that requires both APK and AAB
backup-policy manifest readback. Build 17 adds compiled XML body readback for
both the APK and an AAB-derived universal APK. This evidence does not claim
that an Android vendor, cloud service, or physical device performed backup or
transfer.
