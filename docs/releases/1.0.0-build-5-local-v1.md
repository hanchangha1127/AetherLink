## Reproducibility Qualification

Two isolated clean lane worktrees at different equal-length source roots used
the same host, fixed Xcode/Swift/Android toolchains, one byte-identical Gradle
cache seed, and a fixed canonical Swift scratch policy. Each lane independently
built and packaged the complete unsigned/local Release payload. Both lanes
produced the exact ZIP, manifest, checksum sidecar, and 26-entry archive
inventory recorded above.

Swift package-only compilation uses `-fno-pch-timestamp` so a root-dependent
PCM timestamp does not enter the product object or linked executable.
`resources.txt` uses a closed semantic reachability normalization that retains
each resource identity and reachable/not-reachable state while removing only
the unstable representative reason. Builder and independent readback verifier
implement and test that normalization separately.

This qualifies same-host, fixed-toolchain, fixed-cache-snapshot, equal-length
two-root production-source builds under the recorded canonical scratch and
normalization policies. It does not qualify arbitrary path lengths, arbitrary
roots, a different host or toolchain, signed distribution artifacts, a clean
machine, or physical-device behavior.

## Compatibility And Transition Boundary

- Android Release and macOS package metadata use `1.0.0+5`. Android Debug
  `0.1.0+1` is a separate, non-migratable development lineage that requires a
  clean install and fresh pairing when moving to a production lineage.
- There is no prior production predecessor. N/N-1 install, state, pairing, and
  protocol behavior are not yet qualified.
- Android is unsigned, `arm64-v8a`-only, minimum API 26, and target API 36.
  The macOS package is local ad-hoc, Apple Silicon `arm64`, and macOS 14+.
- The five packaged locales and static artifact structure are verified.
  Physical locale switching, accessibility traversal, launch, QR scanning,
  provider interaction, and real-network behavior are not exercised here.

## Rollback Posture

No production rollback package is claimed. Android channel rollback must ship
a semantically older compatible build with a higher `versionCode`; an ordinary
downgrade is not a supported recovery path. A future macOS rollback should use
the current or immediately previous signed DMG after compatibility and
migration checks, not this local ad-hoc package.
