## Reproducibility Qualification

Two isolated clean lane worktrees at source-root UTF-8 byte lengths 101 and
109 used the same host, fixed Xcode/Swift/Android toolchains, paired clones of
one byte-identical Gradle cache seed, and a fixed canonical Swift scratch
policy. Each lane independently built and packaged the complete unsigned/local
Release payload. Both lanes produced the exact ZIP, manifest, checksum
sidecar, and 26-entry archive inventory recorded above, with
`sourceRootLengthsDiffer=true`.

Swift package-only compilation fixes both the Clang importer working directory
and debug compilation directory while retaining the existing source-prefix
mapping and deterministic linker policy. One compiler-generated escaping
closure diagnostic site uses a canonical source-location alias so its physical
source-path byte length cannot enter the executable. R8 metadata retains the
declared canonicalization policies independently checked by the readback
verifier.

After exact lane comparison, the runner rechecked the source snapshot, Git
references, protected Build 3 sentinel, and expected sidecar identities before
an immutable local publication. It then performed an independent current-source
readback from the main project root. The result records
`independentReadback=true`, `publishedBytesEqualLaneA=true`, and
`sourceSnapshotUnchanged=true`.

This qualifies only the recorded same-host, fixed-toolchain,
fixed-cache-snapshot pair at 101- and 109-byte source roots. The reproducibility
qualification itself does not qualify arbitrary roots or path lengths, a
different host or toolchain, an empty cache, a clean machine, signed
distribution artifacts, app installation or launch, upgrade or rollback,
physical-device behavior, or production readiness. The separate lifecycle
smoke below has a narrower post-publication launch claim.

## Post-Publication Packaged-App Lifecycle Smoke

The separate no-device runner reads back the exact qualified Build 6 archive,
safely extracts only `macos/AetherLink.app`, rechecks the app seal, metadata,
executable identity, and UUID, and then performs two launch-to-termination
cycles. The canonical result is
`dist/lifecycle/macos-packaged-app-build-6-lifecycle-v1.json`. Its identity is
1,311 bytes with SHA-256
`30d90827182e353d9f49fd1fa9edde846bc073f1af5113548f913c7b8af34447`.
It is a post-publication QA result, not an archive payload member.

Each run reached AppKit's finished-launch state with regular activation policy
for the exact extracted executable and bundle ID. Each then recorded
`minimumObservationSeconds=5.0` and `observationDeadlineReached=true`, accepted
an identity-rechecked exact-PID termination request, and exited with code zero.
The second run used a different owned process.

The runner configures an isolated temporary Core Foundation user home, temp
directory, and runtime-identity file override. Its QA-only sandbox preflight
records `temporaryCFUserHomeConfigured=true`,
`nonTemporaryWriteDeniedByPreflight=true`, and
`afInetBindDeniedByPreflight=true`; no unisolated fallback is allowed.
Termination rechecks the executable path and bundle ID in the same AppKit
operation before acting.

The three expected Application Support files were present after each run.
That observation does not prove the second process opened or read them. The

## Compatibility And Transition Boundary

- Android Release and macOS package metadata use `1.0.0+6`. Android Debug
  `0.1.0+1` is a separate, non-migratable development lineage that requires a
  clean install and fresh pairing when moving to a production lineage.
- There is no prior production predecessor. N/N-1 install, state, pairing, and
  protocol behavior are not yet qualified.
- Android is unsigned, `arm64-v8a`-only, minimum API 26, and target API 36.
  The macOS package is local ad-hoc, Apple Silicon `arm64`, and macOS 14+.
- The five packaged locales and static artifact structure are verified.
  The separate lifecycle smoke covers only the two bounded macOS process
  launches described above. Physical locale switching, accessibility
  traversal, UI correctness, QR scanning, provider interaction, and
  real-network behavior are not exercised here.

## Rollback Posture

No production rollback package is claimed. Android channel rollback must ship
a semantically older compatible build with a higher `versionCode`; an ordinary
downgrade is not a supported recovery path. A future macOS rollback should use
the current or immediately previous signed DMG after compatibility and
migration checks, not this local ad-hoc package.
