## Dependency And License Inventory

The catalog covers 350 unique Maven coordinates from all six Gradle lock
files; SwiftPM has zero external dependencies. The SPDX document describes one
AetherLink root plus 350 Maven packages. It contains 692 exact role relationships:
202 runtime, 155 build dependency, and 335 build tool
relationships. Two hundred packages have more than one role. V2 emits every
unique applicable package-to-root role and does not invent package-to-package
edges.

The deterministic namespace binds the release identity, compliance profile,
catalog SHA-256, metadata SHA-256, and source snapshot SHA-256. The official
SPDX 2.3 JSON schema accepts the archived document.

The catalog preserves POM URL, size, SHA-256, parent chain, and parsed license
declarations. Original POM bodies are not archived.
License/NOTICE texts are not archived.
The offline checker does not re-fetch or re-parse those originals.
It therefore proves catalog-derived SPDX/text consistency and the
recorded identities, not the authenticity of unavailable POM bytes,
attribution or notice completeness, binary/source license coverage, legal
compatibility, or legal advice. All third-party `licenseConcluded` values
remain `NOASSERTION`; 25 coordinates retain
`licenseDeclared=NOASSERTION`.

The release build and independent readback are offline. Network access exists
only in the explicit catalog maintenance command:

```sh
python3 -B script/generate_release_compliance.py refresh
```

Build 7 remains readable through frozen, profile-less V1 rules: its 350 SPDX
relationships were one-per-package precedence-compressed relationships
(202 runtime, 141 build dependency, and 7 generic dependency). That historical
shape lost additional roles for 200 multi-role packages and is not presented
as exact scope. Builds 1 through 6 retain manifest schema 1 and no compliance
members.

## Rollback Posture

No production rollback package is claimed. Android channel rollback must use a
compatible semantically older build with a higher `versionCode`; ordinary
downgrade installation is not a supported recovery path. A future macOS
rollback should use the current or immediately previous signed DMG only after
compatibility and migration checks, not this local ad-hoc archive.
