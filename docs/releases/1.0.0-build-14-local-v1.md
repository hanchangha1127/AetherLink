## Android Research Notebook Lifecycle

target atomically. A restored confirmation rebinds only while the trusted
Runtime device ID and fingerprint, notebook ID, session ID, and archived state
still match the current catalog. Temporary absence is tolerated while the
catalog remains unresolved; absence invalidates the confirmation only after an
authoritative catalog snapshot completes. An active target, same-session
replacement notebook, or different trusted Runtime clears the confirmation
immediately. Rejecting stale restored state never invokes deletion.
